# 0047. 外に作用しない n8n のノードは、「実」でなく「非保護」のステップにする

- 状態: 承認
- 日付: 2026-10-07
- 関連: 不変条件 4・5・10、ADR 0003（作用の型）、0042（n8n との統合）

## 背景

kairo-n8n の変換器（ADR 0042）は、n8n のノード（`v1-node`）をすべて `n8n.node` のステップにしている。`n8n.node` の作用は「実」である。どのノードが外に作用するかを変換器は知らないので、不変条件 10（宣言のない作用は実）に従った。

実のステップは、意図の記録が耐久化するまでワーカーに渡さない（不変条件 4）。2026-10-07 の計測では、同期ありで 4 ノードのワークフローを動かすと、実行ごとに同期を 5 回ほど順に待った。macOS では 1 回に十数 ms かかり、c=8 で 17 rps まで落ちた。Linux でも、ノードごとの耐久化の待ちが遅延に効いている。

しかし、n8n のノードの多くは外に作用しない。Set・If・Switch・Merge・Filter などは、入力から出力を計算するだけである。再実行しても同じ結果になり、外には何も起きない。こうしたノードまで実として扱うと、守るべきものがないのに耐久化を待つことになる。

## 決定

変換器は、ノードの型で作用を決める。外に作用しないと確かめた型の一覧にあるノードは、非保護のステップ（`n8n.node.pure`）にする。それ以外は、今までどおり実（`n8n.node`）にする。

- **一覧（`compat/n8n` の `pureNodeTypes`）:** 入力から出力を計算するだけで、外部への通信も、資格情報も、時刻や乱数による副作用も持たない n8n の組み込みノードだけを載せる。最初の一覧は次のとおり（型ごとに、ソースを読んで確かめてから載せる）。
  - `n8n-nodes-base.set`、`if`、`switch`、`merge`、`filter`、`noOp`、`splitOut`、`aggregate`、`sort`、`limit`、`removeDuplicates`、`renameKeys`、`summarize`
- **載せないもの:** HTTP・DB・メールなどの外部とのやり取り、Code ノード（`this.helpers` で外に出られる）、資格情報を使うノード、コミュニティのノード、一覧にない型。迷ったら載せない（不変条件 10 と同じ向き）。
  - Wait ノードは、待ちの宣言（ADR 0045）を返すだけで外に作用しないが、今回は載せない（計測で効果を見てから決める）。
- **アクション:** `n8n.node.pure`（`EffectUnprotected`）を足す。kairo-worker は、`n8n.node` と同じ処理で両方を受ける。
- **再実行の扱い:** 非保護のステップは、結果がわからなくなったら（ワーカーの切断、再起動）再実行する。一覧のノードは、再実行しても外に何も起きないので問題ない。
- **変換器の版:** `ConverterVersion` を上げる。同じワークフローでも作用が変わるので、計画の名前（ハッシュ）が変わる。動いている実行は、古い計画のまま終わる。

## 結果

- 外に作用しないノードのステップは、耐久化を待たずにワーカーに渡る。外に作用するノードだけが、意図の記録を待つ。
- 作用の型を、実装（変換器）が宣言してコンパイル時に決める（AGENTS.md の「作用は実装側が宣言する」と同じ）。実行時には変えない。
- **新しく守ること:** 一覧に型を足すときは、その型のソースを読み、外に作用しないことを確かめる。n8n の版が上がって、ノードの振る舞いが変わることもある。一覧は、n8n の版ごとに見直す。
- **テスト（足す）:**
  - `compat/n8n`: 一覧の型は `n8n.node.pure`（非保護）に、それ以外は `n8n.node`（実）になること。一覧にない型、コミュニティのノード、Code ノードは実のままであること。
  - 実機（n8n）: engine v2 と記録が一致したままであること。同期ありで、計測の値が上がること。

## 検討した代替案

- **すべて実のまま。** 正しいが、外に作用しないノードにまで耐久化の待ちを払う。n8n のワークフローでは、Set や If が多くのノードを占めることが多い。
- **すべて非保護にする。** HTTP やメールのノードが、再起動の後に二重に実行されうる（不変条件 5 に反する）。
- **ノードの作用を、実行時にワーカーが申告する。** 作用は実装が宣言し、コンパイル時に確定する（AGENTS.md）。実行時に変えると、意図の記録を待つかどうかを、渡す前に決められない。
- **n8n のノード定義から自動で判定する（資格情報の有無など）。** 資格情報を持たないのに外に出るノード（HTTP Request の認証なし、RSS など）がある。一覧で明示する方が確か。

## 実装で詰めた詳細（2026-10-07 追記、ADR 0017）

- **一覧から `removeDuplicates` を外した（決定より狭くした）。** v2 には「前の実行までに見た項目を除く」使い方がある。この使い方は、実行をまたいで状態を n8n の側に書き込む。外に作用しないとは言えないので、実（`n8n.node`）のままにした。テストでも、実のままであることを確かめている。
- **ほかの型を確かめた結果:**
  - `set` が 2 進データを扱うのは、入力を読むだけ。
  - `merge` の SQL のモードは、サンドボックスの中で alasql を動かし、ファイルにも外部にも触れない。
  - `sort` のコードのモードは、タスクランナーの中で動き、外への口を持たない。
  - `if`、`switch`、`filter`、`noOp`、`splitOut`、`aggregate`、`limit`、`renameKeys`、`summarize` は、外部とのやり取り・資格情報・実行をまたぐ状態を持たない。
- **再実行の上限:** 非保護のステップは、試行の上限を 3 回にした（間隔は既定の 200ms から倍に伸びる）。これは非保護のステップの既定の値と同じ。
  - 再実行するのは、結果がわからないとき（ワーカーの切断など）と、渡す前の失敗（入力の解決など）だけ。
  - ノード自身のエラーは、kairo-worker が再実行してよい印（retryable）を付けずに返すので、engine v2 と同じく再実行しない。
- **実装の場所:** `compat/n8n/convert.go` の `pureNodeTypes`、`pureNode`、`ActionPureNode`（`n8n.node.pure`）。`ConverterVersion` を 2 に上げた。kairo-worker は、`n8n.node` と `n8n.node.pure` の両方を受ける。
- **テスト:** `TestPureNodeTypes`。一覧の型（set、if）は非保護になる。httpRequest、code、removeDuplicates、コミュニティのノード、型のないノードは、実のままになる。
