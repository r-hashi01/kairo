# 0008. 16 KiB を超える出力はブロブにし、型付きフィールドは状態に残す

- 状態: 承認（2026-10-01）
- 日付: 2026-09-30
- 関連: FR6 / 要件の未決事項 3 / 待機中の1実行あたり ≤ 20KB

## 背景

要件の未決事項 3 は、変数を値で持つか参照で持つかの境界だった。LLM の出力は大きくなりうる。一方でコアは I/O できないので、分岐や map の対象はブロブの外に必要になる。

## 決定

- 出力が `BlobThreshold`（既定 16 KiB）を超えたら、ワーカー側の goroutine（`Engine.Complete`）で内容ハッシュをキーにブロブストアへ書く。状態には次の形のエンベロープを持つ。

  ```
  {"$blob":"sha256:…","size":N,"fields":{…}}
  ```
- `fields` には、ノード仕様の Outputs で宣言したフィールドを残す（出力が JSON オブジェクトの場合）。
  - `list` 型はサイズによらず残す（map の対象になるため）。
  - それ以外の型（text / any を含む）は、値が 1 KiB 以下のときだけ残す。
- ブロブの奥を参照する入力は、コアが遅延参照 `{"$blob":…,"$path":…}` を作る。ディスパッチ時（`ResolveInput`）にシャードの外で解決する。

## 結果

- 条件分岐と map は、常に I/O なしで評価できる。
- 待機中の状態は小さい（実測 1.7 KB、退避後 0.9 KB。ペイロードは除く）。
- 16 KiB は経験則の値で、まだ計測に基づいていない。

## 検討した代替案

- 常に値で持つ: 状態とログが肥大し、スナップショットも重くなる。
- 常に参照で持つ: 小さな値でも I/O が入り、分岐の評価にもブロブの読み込みが必要になる。
