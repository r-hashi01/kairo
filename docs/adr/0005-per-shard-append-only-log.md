# 0005. 耐久性ログはシャード×ティアごとの追記ログとし、group commit する

- 状態: 承認（2026-10-01）。LSN の数え方と「圧縮なし」は 0016 により置き換え
- 日付: 2026-09-30
- 関連: FR6 / 不変条件 7

## 背景

ランタイムがストレージに求めるのは「追記して、障害範囲の外から確認を受け取る」ことだけにしたい（ストレージは外側に置く）。ティアは実行単位で決まる（なし / 共有メモリ / ファイル / 複製）。

## 決定

- `wal.Sink` インターフェースは、`Append(batch)`（耐久化してから返る）、`ReadAll`、`Close` の 3 つだけを持つ。書き込み系の操作は `Append` だけ。実装はファイル（`FileSink`）とメモリ（`MemSink`）。
- シャードごと、ティアごとに 1 本のログを持つ。`Committer` の goroutine が、書き込み中に溜まったバッファをまとめて 1 回の `Append` にする（group commit）。完了したら最大の LSN をシャードに返す。
- 記録の形式は「uvarint 長さ ＋ crc32c ＋ ペイロード」。LSN は保存せず、記録の通し番号として読み取り時に数える。
- `FileSink` は起動のたびに新しいセグメントを作る。途中で切れた末尾は読み飛ばし、書き換えも切り詰めもしない。
- ティア none の実行はログを書かない。

## 結果

- 書き込み中に投入された 200 件が、4 回の書き込みにまとまった（`TestCommitterGroupsWrites`）。
- ログの圧縮（スナップショットより前を捨てる処理）がなく、ログは増え続ける（v0 の制約）。
- LSN を暗黙に数えるため、スナップショットは耐久化済みの LSN までしか含めてはいけない（→ 0011）。

## 検討した代替案

- 実行ごとのログ: ファイル数とシーク回数が実行数に比例する。
- 組み込み DB（bbolt など）: 依存が増え、追記のみという性質も弱まる（→ 0014）。
