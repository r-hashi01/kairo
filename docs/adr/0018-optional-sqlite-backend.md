# 0018. 保存先の既定はファイル形式とし、SQLite は別モジュールの任意の実装として試す

- 状態: 承認（2026-10-01）
- 日付: 2026-10-01
- 関連: ADR 0005, 0014, 0016

## 背景

ログ（WAL のセグメント）とスナップショット（ディレクトリ）は別々の保存先で、両者をトランザクションなしで整合させている。ADR 0016 の実装で手間取った点の多くは、ここから来ていた。

- チェックポイント記録を書く順序
- ディレクトリの fsync
- 削除待ちの記録の保持
- RunID 再利用時の競合

SQLite なら、これらを 1 トランザクションにまとめられる可能性がある。一方で、ADR 0014 は本体の依存をゼロにすると決めている。利用者の判断は「指定がなければファイル形式がよい」。

## 決定

### 既定と配置

- 何も指定しなければ、保存先はこれまでどおりファイル形式とする（`wal.FileSink` と `blob.Dir`）。既定は変えない。
- SQLite 版は、リポジトリ内の別モジュール（`store/sqlite`。独自の `go.mod`）に置く。本体のモジュール（`kairo`）からは参照しない。組み込み側が `Config.Sinks`、`Config.Snapshots`、`Config.Blobs` に明示的に渡したときだけ使われる。
  - 本体の依存ゼロ（ADR 0014）は保つ。依存が増えるのは、SQLite 版を選んだ利用者だけ。

### 第 1 段階（この ADR で承認を求める範囲）

既存のインターフェースのまま、次の 2 つを実装して計測する。インターフェースは変えない。

- `wal.Sink` ＋ `wal.Retirer`
  - シャード×ティアごとに 1 つの DB ファイル。
  - 表は `log(lsn INTEGER PRIMARY KEY, rec BLOB)`。
  - `Append` は 1 バッチ 1 トランザクション。group commit はコミッタのまま。
  - `Retire` は `DELETE WHERE lsn < ?`。
  - WAL モードで `synchronous=FULL`。
- `blob.Store`
  - 表は `kv(key TEXT PRIMARY KEY, data BLOB)`。
- ドライバは `modernc.org/sqlite`（pure Go、cgo なし）を第一候補とする。cgo を要求すると、組み込み先のビルドが重くなるため。計測で性能が足りなければ `mattn/go-sqlite3`（cgo）と比べる。

### 計測と判断の基準

- 同じマシンで、ファイル版と SQLite 版を比べる。
  - `scripts/bench.sh` の各指標
  - 耐久化つきの 5 ノード実行のスループット
  - ログ圧縮を続けたときの DB ファイルサイズ
- 次の 2 つを満たせば、第 2 段階を別の ADR で提案する。
  - 耐久性 ack の p99 が、ファイル版の 1.5 倍以内（Linux では予算 5ms 以内）
  - スループットが、ファイル版の 0.7 倍以上
- 満たさなければ、SQLite 版は採らず、結果だけを記録する。

### 第 2 段階（この ADR の範囲外）

- 「スナップショット＋チェックポイント＋退役」を 1 回の原子的な操作にする保存先インターフェースを足し、ADR 0016 の順序制御を簡単にすること。
- これはエンジンの変更を伴うので、計測結果を見てから別の ADR で判断する。

## 結果

- 第 1 段階では、エンジンも既存の利用者も何も変わらない。
- リポジトリは、`go.mod` を 2 つ持つ構成になる。CI と `scripts/check.sh` で両方のモジュールを検査する必要がある。
- 第 1 段階だけでは、原子性の利点（背景の簡素化）はまだ得られない。この段階で分かるのは、「SQLite にして性能面で困らないか」だけである。
- テスト:
  - ファイル版で使っている Sink / Store のテストを、両方の実装に流せる形にして共通化する。
  - エンジンの耐久化系の統合テスト（リカバリ、ログ圧縮）を、SQLite 版でも流す。

## 検討した代替案

- 既定を SQLite に切り替える: 利用者の判断（指定なしならファイル形式）に反し、依存ゼロの方針（0014）も破る。
- 本体モジュールに SQLite 版を入れ、ビルドタグで切り替える: `go.mod` に依存が載るので、組み込み先の依存グラフに現れる。
- 最初から原子的なインターフェース（第 2 段階）まで作る: 性能を確かめる前にエンジンを変えることになり、採らなかったときに戻す範囲が大きい。
