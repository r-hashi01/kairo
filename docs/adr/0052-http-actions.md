# 0052. アクションを HTTP(S) で呼べるようにする（結果はその場か、後からコールバックで受ける）

- 状態: 承認
- 日付: 2026-10-08
- 関連: 不変条件 4・5、ADR 0009（ワーカーのプロトコル）、0045（待つ結果）、0049（コードで書く API）、0051（常駐しない kairo）

## 背景

常駐しない形（ADR 0051）では、アクションを、ワークフローを動かしているプロセスの中で呼んでいる。サーバーレスでは、これに次の問題がある。

- 長いアクション（LLM の長い生成、外部の重い処理）が、関数の時間の上限（数十秒〜15 分）に当たる。
- アクションを、別の関数・別の場所（GPU のあるマシン、別のサービス）で動かせない。
- ワークフローを動かしている関数が、アクションの終わりを待つ間ずっと動き続け、費用がかかる。

ADR 0051 は、アクションの実行の手段として「HTTP で呼ぶ（サーバーレスの関数）」を挙げたが、その取り決めは決めていない。これは、ランタイムとアクションの間の新しい通信の形式なので、ADR で決める。

## 決定

アクションに URL を宣言できるようにする。URL のあるアクションのステップは、ランタイムが HTTP で呼ぶ。結果は、応答でその場に受けるか、後からコールバックで受ける。

### 宣言

- `defineAction(name, { effect, url, handler, timeout })`（Python は `@k.action(name, url=...)`）。
  - **渡す側**（ワークフローを動かすプロセス）: `url` があれば、HTTP で呼ぶ。
  - **受ける側**（同じ宣言を置いた、URL の先の関数）: `handler` を動かす。
  - 同じコードを両方に置ける。
- 作用（`effect`）は、今までどおり宣言のときに決まる。

### 呼び出し（ランタイム → アクション）

- `POST <url>`。本文は JSON で、次を持つ。
  - ステップ: `run_id`、`step_id`、`act`、`attempt`、`action`、`input`、`idempotency_key`
  - 結果を返す先: `callback`（URL）
- ヘッダー:
  - `Idempotency-Key`: ステップの冪等キー。受ける側は、これで重複を見分けられる。
  - `Kairo-Signature`: 本文と時刻に対する HMAC-SHA256。共有の秘密で作る。
- **応答:**
  - **200:** 結果がその場で出た。本文は結果（`{output}`、`{error, retryable, error_type}`、`{wait: {until, output}}`）。
  - **202:** 受け付けた。結果は、後からコールバックで返す。
  - **4xx:** 確定した失敗（再実行しない）。
  - **5xx、つながらない、時間切れ:** 結果不明。不変条件 5 のとおり、非保護はやり直し、実は要確認で止まる。

### コールバック（アクション → ランタイム）

- `POST <callback>`。本文は `{run_id, act, attempt, result}` で、`Kairo-Signature` を付ける。
- 受けた側（ランタイム）は、署名を確かめ、結果をそのステップのイベント（`step_ok`、`step_err`、`step_wait`）として適用する。
  - 古い試行の結果は、コアが無視する（不変条件 3）。
- 同じコールバックが二度届いても、二度目は無視される。

### 借用（ADR 0051 の段階 3a）

- 202 を受けたステップの借用は、持ち主を `remote:<url>` にし、期限をアクションの時間の上限（`timeout`、既定 15 分）にする。プロセスによる延長はしない。
- 期限までにコールバックが来なければ、ほかの借用と同じく「結果不明」として回復する。
- 呼び出しの前に意図を記録すること（不変条件 4）は、今までどおり。HTTP を送るのは、意図がコミットされた後。

### SDK の差し込み口

- SDK は、Web 標準の `Request → Response` の処理を出す（TypeScript: `k.fetchHandler()`、Python: ASGI の差し込み口）。
  - Next.js、Cloudflare Workers、Deno、Bun、Node（`node:http` からの変換）に、そのまま差し込める。
- 1 つの処理で、2 つの道を受ける。
  - `POST <base>/action`: アクションの呼び出し。`handler` を動かす。
    - すぐ終わるものは 200 で返す。
    - 時間がかかるもの（`async: true` を宣言したアクション）は、202 を返す。プラットフォームの「応答の後も続ける」仕組み（`waitUntil` など）で動かし、終わったらコールバックする。
  - `POST <base>/callback`: 結果の受け取り。ランタイムに適用し、suspend の形なら、ワークフローの続きを動かす。
- 設定: 共有の秘密（`secret`）と、自分のコールバックの URL（`callbackUrl`）。

### 通信の安全（HTTPS を基本にする）

- **既定は HTTPS:** アクションの `url` と、コールバックの `callbackUrl` は `https://` を基本にする。
  - サーバー証明書は検証する。
  - 自分で用意した証明書（社内の認証局など）を使う場合は、信頼する証明書を設定で渡せるようにする。
- **平文の HTTP は例外だけ:** 次のどちらかのときだけ認める。それ以外の `http://` は、アクションの宣言と起動の時点でエラーにする。
  - 宛先が手元（`localhost`、`127.0.0.1`、`::1`）のとき（開発とテスト）
  - 利用者が `allowInsecure: true`（Python は `allow_insecure=True`）を明示したとき（同じプライベートネットワークの中など）
  - SQL の保存先が、検証付きの TLS 以外を拒み、平文には `AllowInsecureTransport` の明示を求めるのと同じ考え方である。
- **署名は HTTPS でも続ける:** 役割が違う。
  - HTTPS は、通信の中身の盗み見と改ざん、つなぎ先のなりすましを防ぐ。
  - 署名（HMAC）は、呼び出しが本当にこのランタイムから来たこと、コールバックが本当にこのアクションから来たことを確かめる。URL を知った第三者が偽の結果をコールバックに送るのを防ぐ。

### 適用の範囲

- 埋め込みのランタイム（ADR 0051）に入れる。
- 常駐の kairod には、今は入れない。kairod には、ワーカーのプロトコル（ADR 0009）と組み込みの HTTP 実行器（`http.*`）がある。

## 結果

- 長いアクションや、別の場所で動かしたいアクションを、サーバーレスでも扱える。ワークフローを動かす関数は、アクションの終わりを待たずに終われる。
- 外に作用するアクションも、意図の記録、冪等キー、結果不明の扱いを、今までどおり守る。
- **新しく守ること:**
  - 署名のない、または署名の合わない呼び出しとコールバックは拒む。
  - 署名には時刻を含め、古いもの（5 分より前）は拒む。
- **形式:** HTTP のアクションの取り決め（本文、ヘッダー、応答の意味）を、新しく決めて保つ。
- **テスト（足す）:**
  - 200 で返るアクション。
  - 202 の後にコールバックで返るアクション（呼んだプロセスは閉じ、コールバックを別のプロセスが受ける）。
  - コールバックが来ないまま期限を過ぎたとき、非保護はやり直し、実は要確認になること。
  - 署名が合わない呼び出しとコールバックを拒むこと。
  - 手元でない `http://` の宣言をエラーにすること。`allowInsecure` を明示すれば通ること。
  - HTTPS（テスト用の自己署名の証明書を信頼させる）で呼べること。
  - 4xx と 5xx の扱い。
  - TypeScript と Python の両方で確かめる。

## 検討した代替案

- **応答で結果を待つだけにする（コールバックなし）:** 呼ぶ側の関数が、アクションの終わりまで動き続ける。時間の上限の問題が残る。
- **キュー（SQS、Pub/Sub など）にアクションを積む:** プラットフォームごとの差し込みが要り、依存が増える。HTTP なら、どの環境にもある。キューに積みたい場合は、URL の先でキューに積めばよい。
- **アクションの側が kairo の DB に直接書く:** アクションの側に DB の接続と、ランタイムの決まり（借用、意図）を持ち込むことになる。結果をランタイムに返し、ランタイムが適用する方が、決まりを 1 か所に保てる。
- **既存のワーカーのプロトコル（ADR 0009）を使う:** ワーカーがつなぎっぱなしで取りに来る形なので、サーバーレスの関数では使えない。

## 実装で詰めた詳細（2026-10-08 追記、ADR 0017）

TypeScript（`sdk/ts/src/http.ts`、`workflow.ts`、`embedded.ts`、`store.ts`）と Python（`sdk/python/kairo_worker/http.py`、`workflow.py`、`embedded.py`、`store.py`）に入れた。依存は足していない（Node は `node:http(s)` と `node:crypto`、Python は `urllib`、`ssl`、`hmac`）。

- **借用の付け替え:** 202 を受けたら、ストアの `handOver`（Python は `hand_over`）で、そのステップの借用の持ち主と期限を書き換える。
  - 書き換えは、(実行, act, 試行) の借用の行がまだあるときだけ行う。
  - 速いアクションのコールバックが、付け替えより先に届くことがある。そのときは結果の適用で借用が終わっているので、付け替えは何もしない。終わったステップに借用が残り直すことはない。
- **時間の上限:** アクションの `timeout` は、今までどおりコアの手順の時間切れのタイマーも仕掛ける。期限を過ぎると、時間切れのタイマーと借用の期限切れの両方が「結果不明」を起こす。後に来た方は古い試行の結果としてコアが無視する。借用は、タイマーの記録が失われた場合の備えになる。
  - 呼び出しの HTTP 自体の待ち時間は、`timeout` と 60 秒の短い方にする。
- **本文の形:** 結果の本文のキーは、両方の言語で snake_case（`output`、`error`、`retryable`、`error_type`、`wait`）にそろえた。TypeScript の SDK の内部の型（`errorType`）とは、送受信の境目で変換する。
  - 2xx でも本文が JSON の結果として読めなければ、結果不明として扱う。
- **応答の扱い:** 4xx は確定した失敗で、再試行しない。5xx、つながらない、時間切れは結果不明で、`retryable` を付ける。非保護は待ち時間（backoff）の後にやり直し、実は要確認で止まる。
- **名前:**
  - TypeScript: `defineAction(name, { url, async, allowInsecure })`。設定は `secret`、`callbackUrl`、`ca`、`allowInsecure`、`waitUntil`。受け口は `k.fetchHandler()`。`node:http` 向けに `nodeHandler()` も出す。
  - Python: `@k.action(name, url=..., async_=True, allow_insecure=...)`。`async` は予約語なので `async_` にした。設定は `secret`、`callback_url`、`ca`、`allow_insecure`、`wait_until`。受け口は `k.asgi_app()`。
- **起動時の検査:** URL のあるアクションがあれば、`start()` は、`secret` と `callbackUrl` があること、`callbackUrl` が上の HTTPS の規則に合うこと、バックエンドが埋め込みであることを確かめ、合わなければエラーにする。
- **非同期のアクションの後始末:** 受ける側は、202 を返した後でハンドラーを動かし、署名したコールバックを送る。送れなかったときは何もしない。呼んだ側では借用の期限が切れ、結果不明として回復する。
- **suspend の形での注意:** ワークフローのコードが例外をすべて捕まえると、待ちを表す `Suspended` まで捕まえてしまう。テストで当たった。捕まえる場合は `Suspended` を投げ直す。
- **テスト:** `sdk/ts/src/http.test.ts` と `sdk/python/tests/test_http.py`（それぞれ 7 件）。Python の側は、テストの中の数十行の asyncio で ASGI のアプリを動かしている。
  - 200 で返るアクション。
  - 202 の後のコールバックを、呼んだのとは別のプロセスが受けて、ワークフローが終わること。アクションは 1 回だけ動く。
  - コールバックが来ないとき、非保護はやり直し、実は要確認になり、実のアクションは二度と呼ばれないこと。
  - 4xx（422）は再試行しないこと。5xx は、非保護ならやり直し、実なら要確認になること。
  - 署名がない、違う秘密、本文の改ざん、10 分前の署名を、`/action` と `/callback` の両方が 401 で拒むこと。
  - 手元でない `http://` を、アクションの宣言と `callbackUrl` の両方で拒むこと。`allowInsecure` で通ること。
  - 自己署名の証明書の HTTPS: 信頼させなければ拒み、`ca` で渡せば呼べること。
