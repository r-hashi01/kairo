# 0004. 状態は先に適用し、外に出る作用だけをログの耐久化まで保留する（出力コミット）

- 状態: 承認（2026-10-01）
- 日付: 2026-09-30
- 関連: FR6（実の命令の順序ルール）/ 不変条件 3, 4

## 背景

要件の順序ルールは、実の命令を「それより前の遷移と意図の記録が耐久化された後」にしか発行しないことを求めている。全イベントについて耐久化を待ってから適用すると、ノード間の受け渡しに fsync の遅延が毎回乗る（p99 ≤ 1ms の予算を守れない）。

## 決定

- イベントはすぐ状態に適用し、同時にログバッファに積む。
- 外に出る作用のうち、次の 2 つは `hold` で保留する。ログがその LSN まで耐久化したら（`ack`）順に解放する。
  - 実の命令: 解放前に `EvIntent` を適用してログに書く。この意図の LSN まで待つ。
  - 実行の完了通知: `lastLSN` まで待つ。
- 非保護の命令はすぐディスパッチする。クラッシュしても再実行すれば済む。
- 実の命令の結果は通常のイベントとしてログに入る。後続の実の命令は自分の意図を記録してから待つ。その意図の LSN は結果の記録より後ろにあるので、「記録された結果だけを根拠にする」という要件も満たせる。

## 結果

- 非保護の作用だけが続く経路は fsync を待たない（受け渡し p99 は約 0.3〜1ms）。
- クラッシュすると、耐久化前に適用した状態は失われる。ただし外にはまだ何も出ていないので、リカバリ後にやり直せる。
- `TestRealCommandWaitsForDurableIntent` が、ack を遅らせたログで順序を検証する。

## 検討した代替案

- 全イベントを耐久化後に適用する: 単純だが、すべての受け渡しに fsync が乗る。
- 実の命令だけ同期的に書く: シャードループがブロックし、不変条件 6 を破る。
