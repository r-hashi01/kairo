# 0011. 待つだけの実行はスナップショットにしてメモリから外す（耐久化済みの LSN まで）

- 状態: 承認（2026-10-01）
- 日付: 2026-09-30
- 関連: FR9 / 不変条件 8

## 背景

長時間待つ実行（人の承認、Webhook、長いタイマー）を、メモリに載せたままにしたくない。スナップショットがログの LSN を参照する以上、クラッシュで失われうる位置を参照してはいけない（→ 0005）。

## 決定

- 実行が quiescent（実行中の命令がない）で、保留中の作用がなく、次の起床が `EvictAfter`（既定 2 秒）より先のとき、状態を符号化して外す。
- ログが `lastLSN` まで耐久化していなければ、耐久化を待ってから外す（`hEvict` として hold する）。
- ティア file 以上では、スナップショットを `snap/<run>` に原子的な置き換えで書く。1 つの実行への書き込みは直列化する（`writing` フラグ）。それ未満のティアでは、符号化したバイト列をメモリに持つ。
- イベントが届いたら復元し、復元中に届いたイベントはキューに溜めて順に適用する。
- リカバリは、スナップショットの LSN より後ろのイベントだけを適用する。

## 結果

- 待機中の 1 実行あたり約 0.9 KB（実行のエントリとタイマーのエントリ。退避時）。
- 書き込みの直列化は、古いスナップショットが新しいものを上書きする競合を実装中に見つけて足した。

## 検討した代替案

- 常にメモリに持つ: 100 万件 × 状態サイズがそのままメモリに乗る。
- 退避したら即座に書き込み、LSN の条件は付けない: 途中で切れたログの末尾と食い違い、リカバリでイベントを取り違える。
