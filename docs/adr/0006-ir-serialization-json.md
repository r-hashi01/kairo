# 0006. IR の直列化形式は JSON とし、計画はノード仕様と組にして凍結する

- 状態: 提案（v0 実装済み）
- 日付: 2026-09-30
- 関連: FR1 / 要件の未決事項 1

## 背景

要件の未決事項 1 は、IR の直列化形式（Protobuf / JSON）だった。計画はランタイムに依存しない表現で、一度だけコンパイルして不変のまま共有する。リカバリした実行は、開始時と同じ計画で再開する必要がある。

## 決定

- 定義（`ir.Definition`）は JSON にする。ホットパスで IR を読むことはない（コンパイル済みの `ir.Plan` を使う）ので、形式の速度は問題にならない。
- 計画のハッシュは、定義と使用したノード仕様の両方から計算する。
- 永続化するときは `ir.Frozen`（定義と、コンパイル時のノード仕様）を保存する。`Thaw` でその仕様だけからコンパイルし直すので、あとでレジストリが変わっても同じハッシュの計画に戻せる。ログの開始記録には計画名とハッシュを残す。

## 結果

- 依存なしで、人が読み書きできる。DSL エディタなど外部ツールから生成しやすい。
- スキーマの強制は弱い。検証はコンパイラ（`ir.Compile`）が担う。

## 検討した代替案

- Protobuf: 型は厳密になるが、コード生成と依存が要る。ホットパスにないので利点が小さい。
- 定義だけを保存して、起動時に現在のレジストリでコンパイルし直す: ノード仕様が変わると、過去の実行を復元できない。
