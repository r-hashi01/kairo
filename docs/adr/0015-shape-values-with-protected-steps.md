# 0015. 値の整形は保護ステップ（pass / append）で行い、IR の構成要素を増やさない

- 状態: 承認（2026-10-01）
- 日付: 2026-09-30
- 関連: FR1, FR3（保護）/ ADR 0001, 0013

## 背景

要件は、IR の構成要素を 5 つ（逐次 / 並列＋合流 / 条件 / 繰り返し / 待機）に限っている。一方で実用上は、値の組み立て（オブジェクトを作る、配列をつなぐ）や、型付きの値へのキャストが要る。

## 決定

- 作用の型が「保護」のステップは、ディスパッチせずにコアの中で評価する。
  - `kairo.pass` と、保護と宣言した任意のアクション: `params` に入力をマージした（入力が優先）オブジェクトを出力する。Outputs を宣言すれば、その出力は分岐に使える型付きの値になる。
  - `kairo.append`: 入力を名前順に並べて 1 つの配列にする（配列は展開し、null は飛ばす）。
- ループの中でステップが自分自身を参照すると、前の反復の値になる。これと append を組み合わせると、追記のみの累積（履歴など）を表せる。
- シグナルは特定の待機ステップ宛てに送れる（`Engine.SignalStep`）。待機一覧（`RunInfo.Waits`）には、map の要素（何を待っているか）を含める。

## 結果

- 構成要素を増やさずに、よくある値の加工を表せる。出力はログに残らない（リプレイで再計算する → 0001）。
- 保護ステップで任意の関数は書けない。計算が要るなら、非保護のステップ（ワーカー）にする。

## 検討した代替案

- 式言語や変換ノードを足す: 構成要素が増え、決定性の検査対象も広がる。
- 任意の Go 関数を保護ステップとして登録できるようにする: 決定性が利用者のコード次第になる。
