# 0013. 条件分岐は bool / int / number / enum の型付きフィールドに限る

- 状態: 承認（2026-10-01）
- 日付: 2026-09-30
- 関連: FR1

## 背景

要件は、条件分岐を型付きフィールドに対してだけ許し、自由文では分岐しないことを求めている。LLM の出力の文字列で分岐すると、再現性も検証性もなくなる。

## 決定

- 条件が参照できるのは、`$input.<f>`（入力の型宣言が要る）、ステップ出力の `<node>.<f>`（ノード仕様の Outputs で宣言が要る）、シグナル待ちの `timed_out` だけ。
- 型が `text` / `any` / `list` のフィールド、宣言のないフィールド、ネストしたパスは、コンパイル時に拒否する（`parsePred`）。
- enum の値は宣言された候補の中から選ぶ。演算子は型ごとに決まっている（bool は eq/ne、数値は比較、enum は eq/ne/in）。
- 値を加工して分岐したいときは、型付きの Outputs を宣言した保護ステップ（pass）を挟む（→ 0015）。

## 結果

- 分岐はコンパイル時に検査でき、ブロブ化された後も評価できる（→ 0008）。
- LLM に分類させてから分岐するには、出力に enum フィールドを宣言する必要がある（意図した制約）。

## 検討した代替案

- 式言語（CEL など）で任意の条件を書けるようにする: 自由文での分岐を防げず、依存も増える。
