# 0009. ワーカープロトコルは、UNIX ソケット上の長さ付きフレーム＋JSON で、pull とクレジット制にする

- 状態: 提案（v0 実装済み）
- 日付: 2026-09-30
- 関連: FR4

## 背景

要件は、ワーカーが UNIX ソケットか gRPC ストリームで命令を取りに来る pull 型で、実装言語を問わないことを求めている。

## 決定

- フレームは「4 バイト長 ＋ 1 バイトの型 ＋ JSON」。メッセージは Hello / Task / Result / Credit / Chunk の 5 種類。TCP でも同じものが動く。
- フロー制御はクレジット制とする。ワーカーは保持できる件数を宣言し、1 件終えるごとに 1 クレジット返す。ディスパッチャはクレジットを超えて渡さない。
- ワーカーが切断したとき、ポーラーのチャネルにまだ残っていた命令はキューに戻す。接続の書き込み側がすでに取り出した命令は、結果不明（Unknown）として扱う（実なら要確認、非保護なら再実行）。
  - 取り出した命令は、書き込みバッファに積んだだけで実際には送れていない場合もある。それでも安全側に倒して、区別せず結果不明とする。実の命令が不必要に要確認になることがあるが、二重実行よりはよい。
- Go 版のクライアントは `protocol.Worker`。

## 結果

- 依存なしで、どの言語からでも数十行で実装できる。
- gRPC の周辺ツール（型生成、負荷分散、認証）は使えない。

## 検討した代替案

- gRPC ストリーム: 要件上は同等の選択肢だが、依存とコード生成が増える（→ 0014）。需要が出たら、同じメッセージで追加する。
- push 型（ランタイムがワーカーへ送る）: ワーカーの空き状況をランタイムが推測することになり、背圧がかけにくい。
