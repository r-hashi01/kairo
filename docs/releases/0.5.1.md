## ハイライト

kairo 0.5.1 は、0.5.0 の修正版です。直したのは 2 つです。埋め込みの runtime で、論理
シグナル ID を付けて送り直したシグナルが二重に届く問題と、終わった実行の出力を
インラインにできなかったときに `Wait` が返らなくなる問題です。API とデータの形式は
0.5.0 と同じです。

### 修正

- 埋め込みの runtime（Go の `kairo.Open`、TypeScript、Python）で、待っている wait に
  `SendSignal` / `sendSignal` / `send_signal` で届けたシグナルが、論理シグナル ID
  （`SignalID` / `signalId` / `signal_id`）を wait の結果に残していませんでした。そのため、
  同じ ID で送り直すと最初の受領を返さず、次の wait に同じ中身をもう一度届けていました。
  先に送ったシグナル（wait より前に届いたもの）も同じです。いまは、ADR 0071 のとおり、
  wait の結果が論理 ID を残します。同じ ID で送り直すと最初の受領を返し、中身が違えば
  エラーになります。kairod を使う側は、もとからこのとおりでした（#102）。

- 終わった実行の出力がブロブを参照していて、その中身を読み出せず出力に置き換え
  （インライン）られなかったとき、`Engine.Wait` で待っていた側が起こされず、context が
  切れるまで返りませんでした。これを直しました。インラインの途中に来た `Wait` も同じです。
  いまは、インラインに失敗しても `Wait` が返ります。そのときの出力は参照のままですが、
  その参照の先のブロブは消さずに残すので、読めます。後片付けは、再起動のときに
  リカバリがやり直します（#96）。

## アップグレード

0.5.0 からは、版を上げるだけで移れます。設定、保存したデータ、ワーカーのプロトコルは
変わりません。
