## Highlights

kairo 0.5.0 makes code workflows safer to resume across failures and rolling
upgrades, brings the embedded and kairod-backed SDKs closer to the same API,
and adds provider-aware admission and diagnostics.

### Workflow lifecycle and recovery

- Workflow completion and cancellation now use the first durable settlement;
  the same outcome is returned live and after restart.
- Child workflows belong to their parent tree. Unreached children do not resume
  on their own, unfinished descendants settle before their parent, and external
  workflows can atomically attach to an unfinished parent.
- Transient Store failures stop the current drive without permanently failing
  the workflow. Explicit workflow retry uses the same recovery path.
- Finished embedded workflow trees have bounded retention while preserving
  idempotency and child results for the configured period.

### kairod-backed code workflows

- Go, TypeScript, and Python SDKs retry unconfirmed starts with the same run ID,
  align cancellation and deadlines, and negotiate graceful worker drain for
  rolling upgrades.
- `Resolve`, `Children`, `List`, parent trees, and suspend-mode workflow driving
  are available over kairod.
- Signals-ahead now have durable atomic receipts, logical signal IDs, and an
  only-if-waiting option across processes.
- kairod can own asynchronous HTTP action callbacks and their attempt-scoped
  expiry instead of requiring a resident SDK callback endpoint.

### Admission, limits, and operations

- Durable-start admission adapts to storage pressure with bounded,
  tenant-fair queues.
- Calls can select a runtime destination. Limits support actual weight,
  weight-per-minute budgets, and provider Retry-After responses.
- Embedded processes can share destination rate state through capable Stores.
- Bounded operational metrics cover start confirmation, claims, WAL latency,
  blocked work, worker disconnects, and graceful drain.
- SQLite-backed processes can wake peers with bounded best-effort local
  notifications while SQLite remains authoritative.

### SDK diagnostics

- The embedded Go, TypeScript, and Python SDKs can replay a code workflow from
  saved terminal call records without running actions, advancing waits, or
  changing durable state.
- Record-only replay returns the reached-call trace and stops at a missing,
  unfinished, blocked, or trimmed call. Parent replay treats a child workflow
  as one recorded call; replay the child ID explicitly to inspect its internals.

## Upgrade notes

- Go builds use Go 1.27.4.
- New worker and HTTP capabilities are negotiated; an SDK does not use an
  optional capability until kairod acknowledges it.
- Record-only replay is currently for embedded code workflows while their tree
  is retained. It does not apply to kairod or graph runs.
- No release tag or package is created by the preparation pull request. The
  nested Go module tags must be pushed first, followed by `v0.5.0` alone.
