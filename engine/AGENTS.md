# engine/ — シャードとリカバリ

- `shard.loop` は、そのシャードの実行を1つの goroutine で所有します。実行の状態にロックはありません。ループの中では I/O もブロックもしません。I/O は `e.doIO` かコミッタに任せ、結果は `inbox.Push` で受け取ります。
  - 例外は終了マーカーの索引（`doneIndex`、ADR 0027）です。`Submit` などが別の goroutine から読むので、`RWMutex` で守ります。ループが持つのはマップの操作の間だけで、その中で I/O や待ちをしてはいけません。
- 終わった実行の後片付け（ブロブ・スナップショットの削除、ピンの解除）は、終了マーカーが耐久化してから行います（`addMarker` の `after`）。この順序を崩すと、再起動で「終わったはずの実行」がまた始まります。
- 状態を変えるのは `shard.event` だけです。適用に成功したイベントは、すぐ `record` でログバッファに積みます（順序は適用順と同じ）。
- 外に出る作用のうち、実の命令と完了通知は `hold` を通します。ログがその LSN まで耐久化してから解放します。非保護の命令はすぐ出してかまいません。
- 退避（`maybeEvict`）は、実行が quiescent で、保留中のものがなく、ログが `lastLSN` まで耐久化済みのときだけ行います。
- ログの退役（ADR 0016）は `maybeCompact` が決めます。実行が必要とする最小の LSN は `run.pin()` です。スナップショットやチェックポイントの流れを変えるときは、`pin` の前提（`pendSnap` / `postSnap` / `s.pins`）が崩れないかを確認します。
- ログの記録形式（`records.go`）を変えるときは、既存のログを読めるようにしておきます。
- 並行処理に触ったら `scripts/check.sh --race` を実行してください。
